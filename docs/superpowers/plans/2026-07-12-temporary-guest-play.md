# Temporary Guest Play Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let learners press **Play as Guest**, access all learner gameplay without Supabase login, and automatically lose guest-owned progress on sign-out or browser/app close.

**Architecture:** Retain the existing synthetic local guest `User`, but move guest identity/profile and guest-owned caches from persistent `localStorage` to `sessionStorage`. Centralize guest-aware storage selection and cleanup in the guest session utility, keep all Supabase account paths unchanged, and preserve the existing `isGuest` gates that prevent remote writes.

**Tech Stack:** React 19, TypeScript 5.9, React Router 7, Supabase JS 2, Vite 7, Node test runner.

## Global Constraints

- Guests can access all learner-facing games and resources but never manager/admin privileges.
- Guest state survives refreshes in the same browser tab and resets on sign-out or browser/app session end.
- Guest-owned progress never writes to Supabase or persistent local storage.
- Existing Supabase account behavior remains unchanged.
- Add no new dependency.
- Validation is Tier 3 and must include desktop plus mobile/tablet coverage, with physical versus emulated checks stated honestly.
